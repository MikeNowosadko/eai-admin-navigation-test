EAI · the build stage

Four ways to ask somebody a question
inside a tool we don't own.

The agent has finished researching and must not build anything until a human says yes. That's the question. The four rungs differ in exactly one way — who draws the box it appears in — and everything else follows from that.

The one idea

It's a dial, from “they draw it” to “we draw it”.

Not four unrelated technologies. One dial with four notches. As you turn it to the right you get more control over what a person sees, and fewer tools that will do it for you. That trade is the whole subject.

They draw itWe draw it
1 · TextWe send words. They print them. Nobody drew anything.
2 · FormWe send a description of the question. They build the box out of their own parts.
2b · LinkWe send a URL. They ask “open this?”. Our page opens in the browser.
3 · AppWe send real HTML. It renders inside their window — and they hand us their colours.

See it

The same question, four ways, three tools.

Left is what we author. Right is what a person sees. The point of the playground is that the left side barely changes and the right side changes completely. Rungs a tool can't do are struck through.

The bit that matters

    
Rung 2 and rung 3 are opposites, not neighbours.

    
They look adjacent because both produce a nice-looking card instead of a wall of text.
      But they are built the opposite way round, and that decides what you can and cannot ask for.


    

      

        Rung 2 · Form
        
We send the question.
They build the UI.

        
Like ordering a form from a print shop. You say “I need one question with three
          options.” They print it — on their letterhead, in their typeface, at their size.
          Every shop prints it differently and you never see the press.

        

          
We control

          
The wording. The options. Which fields exist.

          
They control

          
Every pixel. Layout, colour, type, buttons, keyboard behaviour.

          
The hard limit

          
You may only order from their catalogue, which is six controls: text box,
            number, checkbox, pick one, pick one with labels, pick several. That's it. No image,
            no table, no diff, no chart, no preview, no link that isn't text.

          
Costs us

          
An afternoon. It's a JSON schema.

          
Works in

          
Claude Code, Codex, VS Code, Cursor. Not Copilot CLI or Gemini CLI.

        

      


      

        Rung 3 · App
        
We build the UI.
They lend us the paint.

        
Like hanging your own picture in someone's gallery. You paint it; they frame it, hang
          it, and hand you their paint tin first so it matches the room. If they redecorate, your
          picture changes with it.

        

          
We control

          
Everything inside the frame. It is a real web page — anything HTML can do.

          
They control

          
The frame, the sandbox, and the palette. They pass us CSS variables:
            --color-background-primary, --color-text-primary,
            --font-sans, --border-radius-md, light or dark, their fonts.

          
The hard limit

          
Almost none, on what you can draw. The limit is where it runs.

          
Costs us

          
Building and maintaining a real interface, plus a message channel to talk to the host.

          
Works in

          
VS Code, Cursor, Claude Desktop, ChatGPT. None of the command-line tools —
            and the command line is where our pipeline lives.

        

      

    


    

      Rung 2 is their design carrying our content. Rung 3 is our design wearing their skin.
      If you remember one line from this page, that's the one.

      same card — same HTML, same markup, byte for byte. The only difference is which
      tool it landed in, because each one handed it a different set of CSS variables on the way in.
      We didn't write a VS Code version and a Claude version. We wrote one, and asked for
      var(--color-background-primary) instead of picking a colour.

Choosing

    
One test: can the question be answered by picking from a list?

    
If yes, rung 2 is enough and far cheaper. If a person needs to look at something
      before they can answer, rung 2 physically cannot carry it and you're on rung 3 or the browser.


    

      
“Proceed anyway? yes / no”Rung 2

      
“Which of these three architectures?”Rung 2

      
“Which of these files may I touch?” (pick several)Rung 2

      
“Here are the 40 files I'd change — is that right?”Rung 3

      
“Here's the screen I built. Approve it?”Rung 3

      
“Tests are failing. Here's the diff and the log.”Rung 3

      
“Working… 6 of 11 tasks done.”Rung 1

    


    
Which produces an uncomfortable finding: most of our interesting gates are
      rung 3 gates, and rung 3 doesn't run in the command-line tools our pipeline lives in. That's
      what rung 2b — the link out to the browser — is for. It's the only way to show somebody a picture
      inside Claude Code, and the price is that they leave the window.

The catch

    

      
None of rungs 2, 2b or 3 are available to us today.

      
All three are things an MCP server does. Gofer right now is a set of markdown
        command files that the harness's own agent reads and follows — it can print text, and
        that is the end of its powers. Rung 1 is all we have.

      
  gate reached in /5_gofer_implement
       ↓
  call a tool on our own MCP server
       ↓
  server asks the harness for input
       ↓
  harness draws its own card   ← rungs 2, 2b, 3 live here
       ↓
  accept / decline comes back as data, not as typing

      
So it's one decision, and it's binary: do we ship an MCP server alongside the plugin?
        If no, the build stage is text forever and the state machine is a much smaller study.
        If yes, all four rungs open at once and the fallback ladder becomes the design problem.

    

  


  
  

    
The rule that follows

    
Text isn't the fallback. Text is the source of truth.

    
Every gate gets written as words first and must be answerable by typing. The richer rungs
      are affordances over the same decision — never a different decision, never an extra one.
      Otherwise the Copilot CLI user is playing a different game from the VS Code user, and we'd be
      maintaining four products.

    
Which also means the ladder degrades in one direction only, and never loses the question:

    
one gate, authored once
  ├─ 3 · App     VS Code, Cursor, Claude Desktop   our card, their paint
  ├─ 2b · Link   Claude Code, VS Code              our card, in the browser
  ├─ 2 · Form    Claude Code, Codex, VS Code       their card, our question
  └─ 1 · Text    everything, always                the words, and what to type
