Getting to /eai

The same flow, run twice. It ends where we lose control: the AI tool opens as somebody else's window, empty, and nothing we ship can write a word in it — so the instruction and a short video come beforehand, in the web app and again on the setup app's last screen. What's being watched is whether they type /eai unaided, and whether anyone plays the video. The only difference between these two is whether an AI tool is already on the machine.

Reviewing it, rather than playing it

A flow can only be read forwards, one state at a time, and the ninth state is eight clicks away. This is the same app with the journey taken off it — every screen and every failure on one page, side by side, so the error message on the first screen can be read next to the one on the last. It isn't a copy: the app is lifted out of the sign-up flow when the page loads, so it can't fall behind what testers are given.
